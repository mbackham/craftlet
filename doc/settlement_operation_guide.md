# 商家结算管理模块 - 测试清单与操作使用指南

欢迎使用【商家结算管理模块】。本模块针对平台与商家的资金结算需求设计，全流程覆盖了**结算规则配置**、**自动/手动生成结算单**、**审批与打款流程**、**异常资金冻结**以及**发票管理**。

以下是详细的操作指南与测试验证清单，完全按真实的业务流转顺序编写，适合从零开始体验和测试本模块的所有功能。

---

## 阶段一：操作前准备（账号与权限）

> **测试目标**：确保你拥有足够的权限来操作结算模块。

结算模块涉及核心资金数据，权限拆分非常细。系统默认提供以下权限：
- `settlement:read` (查看结算数据)
- `settlement:approve` (财务审批结算单)
- `settlement:payout` (出纳打款与确认)
- `settlement:manage` (风控/超级管理，可修改规则、冻结资金、强制重试)

**操作步骤**：
1. 使用**超级管理员 (Super Admin)** 账号登录后管后台（如果你是默认的 `admin@example.com`，则自带所有权限）。
2. 在左侧菜单点击 **RBAC管理 -> 管理员账号**，确保你的测试账号拥有关联了上述结算权限的角色（例如“财务”角色和“风控”角色）。

## 阶段二：结算规则配置 (Settlement Rules)

> **测试目标**：配置平台的抽佣、压款天数及处罚规则。

结算规则决定了每个商家何时能结算、结算多少钱。默认系统会找“全局规则”，如果没有全局规则，再看有没有“指定商家规则”。

**操作步骤**：
1. 展开菜单 **财务管理 (Finance)** -> 点击 **结算规则 (Settlement Rules)**。
2. 点击右上角 **新建结算规则 (New Settlement Rule)**。
3. 填写以下表单：
   - **适用商家 (Merchant)**：留空（表示作为全局默认规则适用所有商家），或下拉选择特定商家用于特定抽拥。
   - **周期类型 (Cycle Type)**：选择 `t_plus_n` (按天结算) 或 `monthly` (按月结算)。建议测试使用 `t_plus_n`。
   - **T+N 天数 (Cycle Days)**：例如输入 `7`，表示订单完成后7天才允许结算（避免退单风险）。
   - **保证金扣除比例 (Deposit Deduction Rate)**：例如 `0.05` 表示平台抽成 / 扣留 5%。
   - **违约金比例 (Penalty Rate)**：例如 `0.0`。
   - **最低结算金额 (Min Settlement Amount)**：例如 `100`，表示低于100元先不结算，攒够了再结。
4. 点击 **保存**。

**✅ 测试检查点**：
- [ ] 能否成功创建一个 Global Default (全局默认) 的活跃规则？

## 阶段三：获取测试数据（订单与退款）

> **测试目标**：让系统里有钱可结。

只有状态为“已完成(completed)”且超过了 T+N 天数的订单，才符合结算条件。

**操作步骤**：
1. 确保系统内有某个商家的订单（可以在 **订单管理 -> 订单列表** 中查看）。
2. 为了方便测试，你可以在开发环境的终端中（使用 `rails console`），把某几个订单的状态强制改为 `completed`，并把更新时间改到7天前：
   ```ruby
   Order.last(3).each { |o| o.update(status: 'completed', updated_at: 8.days.ago) }
   ```

## 阶段四：生成结算单 (Generate Settlements)

> **测试目标**：触发生效结算单并查看金额明细。

由于结算单默认是系统每天夜里通过定时任务生成的，为了方便测试，我们在页面上提供了一键生成入口。

**操作步骤**：
1. 进入菜单 **财务管理 -> 结算单 (Settlements)**。
2. 点击右上角的 **手动生成结算单** 按钮，并在弹出的确认框中点击“确定”。
3. 页面会提示“任务已提交”，稍微等几秒钟刷新页面，列表中就会出现新生成的【结算单】。
4. 点击操作栏的 **查看 (View)** 进入详情页。

**✅ 测试检查点**：
- [ ] 结算单是否处于 **待审核 (Pending Review)** 状态？
- [ ] 在“结算单信息”面板，核对 **结算周期**与**商家**是否正确。
- [ ] 在“金额明细”面板，检查系统算对了吗？算法如下：
  `结算金额 = (订单总额 - 退款总额) * (1 - 抽成比例) - 违约金`。
- [ ] 拖到页面下方，查看 **结算明细 (Settlement Items)**，里面是否列出了这笔结算包含的具体订单金额/退款金额？

## 阶段五：常规审批与打款流转

> **测试目标**：体验常规的出款全流程。

结算单从生成到商家收到钱，需要多角色接力配合：【财务审批】 -> 【出纳打款】 -> 【确认到账】。

**第一步：财务审批 (Approve)**
1. 在待审核状态的结算单详情页右上角，点击 **审批通过 (Approve)** 按钮。
2. 在弹出的表单界面中，选填审批备注（比如：“系统初账核对无误”）。
3. 提交后，状态变成黄色的 **已审批 (Approved)**。（此时下方审计日志中会留下你的审批人记录与时间）

**第二步：出纳打款 (Payout)**
1. 状态变为已审批后，右上角会出现 **确认打款 (Confirm Payout)** 按钮。
2. 点击按钮，在弹出的表单中，由于涉及真金白银的出账，**必须填写“打款凭证号”**（如银行电子主账号或转账回单流水号）。输入例如 `BANK-T-100234` 然后提交。
3. 提交后，状态变成黄色的 **已打款 (Paid Out)**。

**第三步：确认到账 (Confirm Arrival)**
1. 打款后，若商家确认或网银接口确认已收到了钱，点击右上角的 **确认到账 (Confirm Arrival)**。
2. 状态变为绿色的 **已到账 (Confirmed)**。这笔结算资金圆满闭环！

**✅ 测试检查点**：
- [ ] 这三个动作是否平滑流转？
- [ ] 右侧“审批信息”面板中，是否正确展示了“审批人”、“出纳人”、和“打款凭证号”？
- [ ] 最下方 **审计日志 (Audit Logs)**，是否清晰地记录了你的每一步操作以及 IP 地址？

## 阶段六：异常分支与资金冻结

> **测试目标**：测试发现风险时冻结商家的款项。

如果风控部门发现商家的这批订单涉嫌欺诈、刷单，或平台接到大量客诉，可以紧急拦截资金并冻结该结算单。

**操作步骤**：
1. 请重新生成或找一个处于 **待审核** 或 **已审批** 状态的结算单（只要没打款成功就可以冻结）。
2. 在右上角点击 **冻结资金 (Freeze Funds)**。
3. 弹出红色警告弹窗！系统要求**必须输入冻结原因**。输入“接大量客诉，疑似商品涉假，暂缓结算”。
4. 提交后，状态变成红色的 **已冻结 (Frozen)**。
5. 下方 **异常记录 (Exception Records)** 中会看到一条新生成的 `商家冻结` 异常报告。
6. 被冻结的资金无法再被审批或打款，**必须点击重试 (Retry)** 才能解除冻结，让状态打回“待审核”重新走流程。

**✅ 测试检查点**：
- [ ] 状态是否变红成了“Frozen”？
- [ ] 侧边栏和下方面板是否都展示了红色的冻结原因和异常记录？
- [ ] 重试结算单后，是否成功回到了“待审核”？

## 阶段七：发票管理 (Invoices)

> **测试目标**：测试商家开票申请的后台流转（关联结算）。

平台给商家结算了钱，抽走了佣金，商家会需要发票。此模块用于管理基于结算单的开票流程。

**操作步骤**：
1. 展开菜单 **财务管理 -> 发票管理 (Invoices)**。
2. 点击右上角 **新建发票 (New Invoice)** 手动创建一条测试申请（选择刚才结算完的商家，指定发票类型为“专用发票”，填入税号，状态选择“已申请”）。
3. 在发票详情页，体验一下操作按钮：
   - 点击 **开具发票 (Issue Invoice)**。
   - 接着点击 **寄送发票 (Ship Invoice)**，录入顺丰或圆通的“快递单号”。
   - 最后点击 **确认签收 (Confirm Receipt)** 结束流程。

**✅ 测试检查点**：
- [ ] 发票状态栏的颜色是否根据状态（已申请 待办、已寄送 黄色、已签收 绿色）正确显示？
- [ ] 返回那张具体的结算单（Settlement）详情页，拉到“关联发票”，是否能看到刚才开的这张发票？
